## 修复记录

### 本次修复的问题

#### 1. 客户空间 MissingGreenlet 错误 (P0)

**问题**: 
- 客户列表返回 500 错误
- 错误信息：`MissingGreenlet: greenlet_spawn has not been called`

**根因**:
- `customer_repo.py` 的 `search` 方法没有预加载 relationship
- `_to_dto` 访问 `customer.contacts` 和 `customer.opportunities` 触发懒加载

**修复**:
```python
# 修复前
stmt = select(Customer).where(Customer.is_deleted == 0)

# 修复后
stmt = select(Customer).where(Customer.is_deleted == 0).options(
    joinedload(Customer.contacts),
    joinedload(Customer.opportunities),
)
```

**影响文件**:
- `workspace/api/app/repositories/customer_repo.py`

#### 2. 项目空间系列问题 (P0) - 之前已修复

- MissingGreenlet 错误
- 子API 500错误
- 权限校验缺失

## 系统性风险排查

### SQLAlchemy 异步模式下的 MissingGreenlet 风险

**问题本质**: 
在 SQLAlchemy 异步引擎中，如果在 session 关闭后访问 relationship，会触发懒加载导致 `MissingGreenlet` 错误。

**排查结果**:

| Repository | 状态 | 说明 |
|-----------|------|------|
| project_repo.py | ✅ 已修复 | 使用 joinedload 预加载 |
| customer_repo.py | ✅ 已修复 | 使用 joinedload 预加载 |
| task_repo.py | ✅ 安全 | DTO 不包含 relationship 字段 |
| file_repo.py | ✅ 安全 | 无 relationship |
| ai_repo.py | ⚠️ 待查 | 有 search 方法但未使用 joinedload |
| coach_repo.py | ✅ 安全 | 使用 refresh 预加载 |

**预防措施**:
1. ✅ 所有包含 relationship 的 search 方法必须使用 joinedload
2. ✅ 使用 `unique()` 处理 joinedload 可能产生的重复行
3. ✅ Service 层在 session 关闭前完成所有 relationship 访问
4. ✅ 定期检查新添加的 Repository 是否符合规范
