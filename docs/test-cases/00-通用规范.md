## 一、用例 ID 编号规则

### 1.1 格式

```
TC-{模块代号}-{类型}-{NNN}
```

- `TC` = Test Case 固定前缀
- `{模块代号}` = 见 §1.2
- `{类型}` = `F` 功能 / `I` 接口 / `U` UI
- `{NNN}` = 三位数字，每个模块×类型独立编号，从 001 起递增（不补 0 不跳号）

### 1.2 模块代号表（10 类）

| 代号 | 模块 | 归属文档 |
|------|------|---------|
| `DASH` | 工作台 Dashboard | 01-工作台.md |
| `TASK` | 任务中心 + T 助手 | 02-任务中心-T助手.md |
| `PROJ` | 项目空间 + P 助手 | 03-项目空间-P助手.md |
| `CUST` | 客户空间 | 04-客户空间.md |
| `COACH` | FDE 教练 + C 助手 | 05-FDE教练-C助手.md |
| `FILE` | 文件中心 + F 助手 | 06-文件中心-F助手.md |
| `CHAT` | AI 对话中心 | 07-AI对话中心.md |
| `SET` | 系统设置 | 08-系统设置.md |
| `COP` | Copilot 通用 + 二次确认 | 09-Copilot通用与二次确认.md |
| `COMM` | 跨模块通用 | 10-跨模块通用.md |

### 1.3 ID 示例

| 示例 ID | 含义 |
|---------|------|
| `TC-DASH-F-001` | 工作台模块的第 1 条功能用例 |
| `TC-TASK-I-005` | 任务中心模块的第 5 条接口用例 |
| `TC-COP-U-012` | Copilot 通用模块的第 12 条 UI 用例 |
| `TC-CHAT-F-027` | AI 对话中心模块的第 27 条功能用例 |

### 1.4 ID 唯一性约束

- 全局唯一：所有 11 份文档下的用例 ID 不允许重复
- 不可复用：废弃的用例 ID 不得回收给新用例
- 顺序递增：同模块×类型按创建顺序递增编号

## 二、用例 7 个基础字段

每条用例必须包含以下 7 个字段，缺一不可：

| # | 字段名 | 类型 | 说明 |
|---|-------|-----|------|
| 1 | 用例 ID | string | 见 §一 |
| 2 | 模块 | string | 与 ID 的模块代号对应（中文名） |
| 3 | 标题 | string | 一句话描述，≤ 30 字 |
| 4 | 优先级 | enum | P0 / P1 / P2 / P3，见 §三 |
| 5 | 类型 | enum | 功能 / 接口 / UI |
| 6 | 前置条件 | list | 编号列表：账号、数据、页面状态等 |
| 7 | 测试步骤 | list | 编号列表：每步明确「在哪个对象上做什么操作」 |
| 8 | 预期结果 | list | 编号列表：与步骤一一对应 |

> [!IMPORTANT]
> 步骤与预期结果**必须一一对应**：步骤 1 → 预期 1，步骤 2 → 预期 2，以此类推。这是后续自动化执行（Playwright/Pytest）的核心约定。

### 2.1 用例标准模板

```markdown
### TC-{模块}-{类型}-{NNN} 用例标题

| 字段 | 值 |
|------|-----|
| 模块 | xxx |
| 优先级 | P0/P1/P2/P3 |
| 类型 | 功能/接口/UI |
| 前置条件 | 1. xxx；2. xxx |

**测试步骤**：
1. 步骤 1
2. 步骤 2
3. 步骤 3

**预期结果**：
1. 预期 1
2. 预期 2
3. 预期 3
```

## 三、优先级定义

| 优先级 | 含义 | 触发场景 | 占比目标 |
|--------|------|---------|----------|
| **P0** | 阻塞主流程 | 失败则核心场景无法完成（登录、列表、CRUD 主流程、二次确认核心路径、SSE 流式响应） | ~20% |
| **P1** | 核心功能 | 失败影响主要功能但有变通方案（筛选、排序、批量、各 Copilot 4 大场景） | ~40% |
| **P2** | 次要功能 | 失败影响体验但不影响交付（推荐、统计卡、容量条、面包屑） | ~30% |
| **P3** | 边缘场景 | 边界值、异常输入、罕见组合（超长字符串、特殊符号、空数据态） | ~10% |

### 3.1 P0 用例必须覆盖（强制清单）

| 模块 | P0 主流程 |
|------|----------|
| 工作台 | 首屏加载、4 张统计卡渲染 |
| 任务中心 | 任务列表加载、创建任务、更新状态、T 助手创建任务（actionCard） |
| 项目空间 | 项目详情加载、7 Tabs 切换、风险列表、P 助手风险分析 |
| 客户空间 | 客户列表、客户详情、5 Tabs 切换 |
| FDE 教练 | 4 入口卡渲染、最佳实践搜索、C 助手专家咨询 |
| 文件中心 | 文件树渲染、文件上传、F 助手智能搜索 |
| AI 对话 | SSE 流式接收、@ 引用、模式切换 |
| 系统设置 | 登录、登出、修改密码 |
| Copilot | 助手切换 < 200ms、actionCard 字段对比、二次确认主流程 |
| 跨模块 | 全局导航、Token 过期跳转、权限隔离 |

## 十、二次确认机制 5 种异常路径（强制覆盖）

| 异常 | HTTP | 错误码 | 触发场景 | 用例归属 |
|------|------|--------|---------|---------|
| actionId 不存在 | 404 | BIZ_ACTION_NOT_FOUND (8002) | 伪造 actionId | TC-COP-I-xxx |
| actionId 过期 | 410 | BIZ_ACTION_EXPIRED (8003) | 等待 > 60s 后执行 | TC-COP-I-xxx |
| 用户不匹配 | 403 | BIZ_ACTION_USER_MISMATCH (8004) | A 创建 actionId，B 执行 | TC-COP-I-xxx |
| 工具不匹配 | 422 | BIZ_ACTION_TOOL_MISMATCH (8005) | actionId 对应 batchUpdate，请求 batchDelete | TC-COP-I-xxx |
| 用户取消 | 200 | - | 主动取消 actionCard | TC-COP-F-xxx |

## 十一、用例编写规范（编写人须知）

### 11.1 编写原则

1. **可执行**：步骤明确到「点哪个按钮、输入什么文本」，不要写"操作 xxx"这种模糊描述
2. **可验证**：预期结果可量化（HTTP 状态码、文案、元素颜色、是否可见、是否可点）
3. **独立性**：每条用例独立运行，不依赖其他用例的执行结果
4. **数据复用**：使用 §五 种子数据，避免每条用例自造数据
5. **正向 + 反向**：每个核心功能至少 1 正常 + 1 异常 + 1 边界

### 11.2 禁止行为

- ❌ 步骤与预期不对应（步骤 3 步，预期 5 条）
- ❌ 写"等等"、"诸如此类"等模糊描述
- ❌ 复用全局唯一 ID
- ❌ P0 用例缺少明确的失败影响说明
- ❌ 接口用例只写"返回成功"不写 HTTP 状态码与响应字段

### 11.3 命名风格

- 用例标题使用动宾结构："创建普通任务（主流程）"，避免"测试一下创建任务"
- 异常路径标题加括号说明："创建任务标题超长（边界）"
- UI 用例标题加视觉点："健康度环渐变色与角度（视觉）"
