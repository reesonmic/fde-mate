## 三、优先级定义速查

| 优先级 | 含义 | 占比目标 |
|--------|------|---------|
| **P0** | 阻塞主流程：失败则核心场景无法完成 | ~20% |
| **P1** | 核心功能：失败影响主要功能但有变通方案 | ~40% |
| **P2** | 次要功能：失败影响体验但不影响交付 | ~30% |
| **P3** | 边缘场景：边界值、异常输入、罕见组合 | ~10% |

## 五、推荐执行顺序

### 5.1 冒烟测试（约 30 分钟）

执行所有 P0 用例的精简子集，验证基本功能可用：

1. 登录（TC-SET-F-001）
2. 工作台首屏（TC-DASH-F-001）
3. 8 模块导航切换（TC-COMM-F-001）
4. 任务列表加载（TC-TASK-F-001）
5. 项目详情加载（TC-PROJ-F-001）
6. 文件树加载（TC-FILE-F-001）
7. AI 对话 SSE 流式（TC-CHAT-I-001）
8. T 助手创建任务（TC-TASK-F-020）
9. 二次确认主流程（TC-COP-F-001）

### 5.2 全量回归

按以下顺序执行全部 11 份文档的 P0 → P1 → P2 → P3：

```
P0 全部 (108 条) → 阻塞主流程，不通过则不进入 P1
  ↓
P1 全部 (180 条) → 核心功能
  ↓
P2 全部 (96 条)  → 次要功能
  ↓
P3 全部 (26 条)  → 边缘场景
```

### 5.3 模块独立测试

按文档顺序（01 → 10）逐模块测试，适合并行多人执行。

## 七、用例字段速查

每条用例必含 7 个基础字段（详见 [00-通用规范.md §二](./00-通用规范.md#二用例-7-个基础字段)）：

1. **用例 ID** - TC-xxx-x-NNN
2. **模块** - 中文模块名
3. **优先级** - P0/P1/P2/P3
4. **类型** - 功能/接口/UI
5. **前置条件** - 编号列表
6. **测试步骤** - 编号列表
7. **预期结果** - 编号列表（与步骤一一对应）

## 八、贡献指南

1. **编写新用例前**：先读 [00-通用规范.md](./00-通用规范.md) 全文
2. **新增用例**：在对应模块文档末尾追加，ID 顺序递增
3. **修改用例**：保留原 ID，修改内容
4. **废弃用例**：标记 `[已废弃]` 不删除，ID 不回收
5. **跨模块用例归属**：按"哪个模块的功能"判断，不按"在哪个页面"判断
