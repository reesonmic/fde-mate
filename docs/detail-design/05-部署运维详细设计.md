## 1. 部署架构

### 1.1 整体架构

```
                    ┌─────────────────────────────────┐
                    │         Nginx (Ingress)          │
                    │   :80/:443 → SPA + API proxy     │
                    └──────────┬──────────────────────┘
                               │
                ┌──────────────┼──────────────┐
                ▼              ▼              ▼
        ┌──────────────┐ ┌───────────┐ ┌─────────────────┐
        │  Web (SPA)   │ │ API       │ │ AI Orchestrator │
        │  Vue 3/Nginx │ │ FastAPI   │ │ LangGraph       │
        │  :80         │ │ :8080     │ │ :8090           │
        └──────────────┘ └─────┬─────┘ └────────┬────────┘
                               │                 │
                    ┌──────────┴────────┐        │
                    ▼          ▼        │        │
                 ┌──────┐ ┌───────┐    │        │
                 │MySQL │ │ Redis │    │        │
                 │:3306 │ │ :6379 │    │        │
                 └──────┘ └───────┘    │        │
                    │          │       │        │
                 ┌──────┐ ┌───────┐    │        │
                 │ ES   │ │Milvus │    │        │
                 │:9200 │ │:19530 │    │        │
                 └──────┘ └───────┘    │        │
                               │       │        │
                               └───────┴────────┘
                          HTTP only (internal network)
```

### 1.2 通信边界

| 通信路径 | 协议 | 认证 | 说明 |
|---------|------|------|------|
| Browser → Web | HTTPS | 无 | 静态资源 |
| Browser → API | HTTPS REST/SSE | JWT Bearer Token | 业务请求 |
| API → AI Orchestrator | HTTP | 无(内网) | AI 调用 |
| API → MySQL/Redis/ES/Milvus | TCP | 内网认证 | 数据存储 |
| Web → AI Orchestrator | ❌ 禁止 | — | 前端不得直连 |

## 2. Docker 容器化

### 2.1 多阶段构建

所有服务均采用**多阶段构建**，区分 builder 和 production 阶段：

| 服务 | 基础镜像 | 产物 | 端口 |
|------|---------|------|------|
| API | python:3.11-slim | FastAPI + uvicorn (4 workers) | 8080 |
| Web | node:20-alpine → nginx:alpine | dist/ + nginx.conf | 80 |
| AI Orchestrator | python:3.11-slim | FastAPI + uvicorn (2 workers) | 8090 |

### 2.2 Dockerfile 要点

**API 服务** (`workspace/api/Dockerfile`):
- 多阶段构建，builder 安装 poetry 依赖，production 只拷贝 site-packages
- 非 root 用户 `appuser` 运行
- Healthcheck: `curl http://localhost:8080/health`
- 启动: `uvicorn app.main:app --host 0.0.0.0 --port 8080 --workers 4`

**Web 服务** (`workspace/web/Dockerfile`):
- Build stage: `npm ci` → `npm run build`
- Production: nginx:alpine 托管 dist/
- nginx 配置包含 API 代理、SSE 代理、Gzip、SPA fallback

**AI Orchestrator** (`workspace/ai-orchestrator/Dockerfile`):
- 同 API 的多阶段模式
- 2 workers (AI 请求较重)
- 依赖: LangGraph、langchain、httpx

### 2.3 .dockerignore

- `__pycache__`, `.pytest_cache`, `.mypy_cache`, `tests/`
- `.env*` (除 `.env.example`)
- IDE 配置 `.idea/`, `.vscode/`

### 2.4 Docker Compose

```bash
# 开发环境 - 仅启动依赖服务
cd workspace/infra/docker-compose
docker-compose -f docker-compose.deps.yml up -d

# 完整环境 - 所有服务
docker-compose up -d --build

# 查看状态
docker-compose ps

# 查看日志
docker-compose logs -f api
```

**环境变量** (`.env` 文件放在项目根目录):
```env
MYSQL_ROOT_PASSWORD=your-secure-password
JWT_SECRET_KEY=your-jwt-secret-at-least-16-chars
DASHSCOPE_API_KEY=sk-xxx
OPENAI_API_KEY=sk-xxx
```

## 3. K8s 部署

### 3.1 Namespace

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: fde-workbench
```

### 3.2 ConfigMap

```yaml

kind: ConfigMap
metadata:
  name: fde-config
  namespace: fde-workbench
data:
  DATABASE_URL: "mysql+aiomysql://root:$(MYSQL_ROOT_PASSWORD)@mysql:3306/fde_workbench?charset=utf8mb4"
  REDIS_URL: "redis://redis:6379/0"
  ES_URL: "http://elasticsearch:9200"
  MILVUS_HOST: "milvus"
  MILVUS_PORT: "19530"
  AI_ORCHESTRATOR_URL: "http://ai-orchestrator:8090"
  LOG_LEVEL: "INFO"
```

### 3.3 Secrets

```yaml

kind: Secret

  name: fde-secrets
  namespace: fde-workbench

stringData:
  MYSQL_ROOT_PASSWORD: "change-me-in-production"
  JWT_SECRET_KEY: "change-me-to-256bit-secret"
  DASHSCOPE_API_KEY: "sk-xxx"
```

### 3.4 Deployment 示例 (API)

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: fde-api
  namespace: fde-workbench
spec:
  replicas: 2
  selector:
    matchLabels:
      app: fde-api
  template:
    metadata:
      labels:
        app: fde-api
    spec:
      containers:
        - name: api
          image: fde-api:latest
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: fde-config
            - secretRef:
                name: fde-secrets
          resources:
            requests:
              cpu: 250m
              memory: 512Mi
            limits:
              cpu: "1"
              memory: 1Gi
          livenessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 30
          readinessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 10
```

### 3.5 Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: fde-api
  namespace: fde-workbench
spec:
  selector:
    app: fde-api
  ports:
    - port: 8080
      targetPort: 8080
  type: ClusterIP
```

### 3.6 Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: fde-ingress
  namespace: fde-workbench
  annotations:
    nginx.ingress.kubernetes.io/proxy-read-timeout: "300"
    nginx.ingress.kubernetes.io/proxy-buffering: "off"
spec:
  rules:
    - host: fde.example.com
      http:
        paths:
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: fde-api
                port:
                  number: 8080
          - path: /
            pathType: Prefix
            backend:
              service:
                name: fde-web
                port:
                  number: 80
```

### 3.7 HPA (自动扩缩容)

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: fde-api-hpa
  namespace: fde-workbench
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: fde-api
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
```

## 4. CI/CD 流程

### 4.1 GitHub Actions 流水线

```
push/PR → CI Job
  ├── backend-test (pytest + ruff + mypy)
  ├── frontend-test (vue-tsc + eslint + vitest)
  └── orchestrator-test (pytest + ruff)
       ↓ (all pass + push to master)
  build-images
  ├── fde-api:latest
  ├── fde-web:latest
  └── fde-orchestrator:latest
```

### 4.2 流水线配置

- 配置文件: `.github/workflows/ci.yml`
- 触发条件: push to master / pull request
- 缓存: npm cache / poetry cache / Docker layer cache (GitHub Actions cache)
- 超时: 每 job 15 分钟

### 4.3 本地 CI 检查

```bash
# 后端
cd workspace/api
poetry run ruff check app
poetry run mypy app --ignore-missing-imports
poetry run pytest tests/ -v

# 前端
cd workspace/web
npm run lint
npm run test

# AI Orchestrator
cd workspace/ai-orchestrator
poetry run ruff check app
poetry run pytest tests/ -v
```

## 5. 监控告警

### 5.1 应用层监控

**FastAPI 中间件**: 已实现 trace middleware，每个请求生成 `trace_id`

**健康检查**: 所有服务提供 `/health` 端点
```json
{
  "status": "ok",
  "version": "0.1.0",
  "providers": {...}
}
```

### 5.2 Prometheus 指标 (待实现)

推荐集成 `prometheus-fastapi-instrumentator`:
```python
from prometheus_fastapi_instrumentator import Instrumentator

Instrumentator().instrument(app).expose(app)
```

关键指标:
- `http_requests_total` — 请求总量
- `http_request_duration_seconds` — 请求延迟
- `http_request_size_bytes` — 请求大小
- `llm_request_duration_seconds` — LLM 调用延迟
- `llm_token_usage_total` — Token 用量
- `rag_search_duration_seconds` — RAG 检索延迟
- `safety_blocks_total` — 安全拦截次数

### 5.3 Grafana Dashboard (推荐面板)

| 面板 | 指标 | 告警阈值 |
|------|------|---------|
| API QPS | rate(http_requests_total[5m]) | — |
| P99 延迟 | histogram_quantile(0.99, ...) | > 2s |
| 错误率 | rate(http_requests_total{status=~"5.."}[5m]) | > 1% |
| LLM 调用延迟 | rate(llm_request_duration_seconds_sum[5m]) | > 10s |
| Token 用量 | increase(llm_token_usage_total[1h]) | — |
| 安全拦截 | rate(safety_blocks_total[5m]) | 突增 > 10/min |

### 5.4 日志

- **格式**: JSON 结构化日志 (logging middleware 已实现)
- **收集**: Fluent Bit → Elasticsearch → Kibana (EFK)
- **审计日志**: AI Orchestrator 审计日志 (`workspace/ai-orchestrator/audit/`) — JSONL 格式，按天分文件

### 5.5 告警规则 (Prometheus AlertManager)

```yaml
groups:
  - name: fde-alerts
    rules:
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.01
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "API error rate > 1%"

      - alert: HighLatency
        expr: histogram_quantile(0.99, rate(http_request_duration_seconds_bucket[5m])) > 2
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "API P99 latency > 2s"

      - alert: ServiceDown
        expr: up == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "{{ $labels.job }} is down"

      - alert: SafetyBlockSpike
        expr: rate(safety_blocks_total[5m]) > 10
        for: 2m
        labels:
          severity: warning
        annotations:
          summary: "AI safety blocks spike > 10/min"
```

## 6. 运维操作手册

### 6.1 数据库迁移

```bash
cd workspace/api
poetry run alembic upgrade head        # 升级到最新
poetry run alembic downgrade -1        # 回退一步
poetry run alembic current             # 查看当前版本
poetry run alembic revision -m "desc"  # 创建新迁移
```

### 6.2 日志查看

```bash
# Docker Compose
docker-compose logs -f --tail=100 api
docker-compose logs -f --tail=100 ai-orchestrator

# K8s
kubectl logs -n fde-workbench -l app=fde-api --tail=100 -f

# 审计日志
tail -f workspace/ai-orchestrator/audit/audit_2026-05-01.jsonl
```

### 6.3 服务重启

```bash
# Docker Compose
docker-compose restart api

# K8s
kubectl rollout restart deployment/fde-api -n fde-workbench
kubectl rollout status deployment/fde-api -n fde-workbench
```

### 6.4 扩缩容

```bash
# K8s 手动扩容
kubectl scale deployment/fde-api --replicas=4 -n fde-workbench

# HPA 自动 (见 3.7)
```

### 6.5 故障排查

| 症状 | 排查步骤 |
|------|---------|
| API 502 | 检查 pod 是否 Running: `kubectl get pods -n fde-workbench` |
| SSE 断开 | 检查 Ingress `proxy-read-timeout` 和 `proxy-buffering` 配置 |
| DB 连接失败 | 检查 MySQL 连接数: `SHOW PROCESSLIST` |
| LLM 调用失败 | 检查 Circuit Breaker 状态: `/ai/health` |
| 内存泄漏 | `kubectl top pods -n fde-workbench` |
