## 一、API 设计

### CR-BE-API-001 路由必带版本号

所有 API 必经 `/api/v1/*`，便于未来灰度升级。

❌ Bad：

```python
@router.get("/tasks")
async def list_tasks(): ...
```

✅ Good：

```python
# main.py
app.include_router(tasks_router, prefix="/api/v1/tasks", tags=["tasks"])

# tasks/router.py
@router.get("")
async def list_tasks(): ...   # 实际路径 /api/v1/tasks
```

### CR-BE-API-002 Request / Response 必用 Pydantic Schema

禁止用 `dict` 接收请求或返回响应（无校验、无文档、无类型）。

❌ Bad：

```python
@router.post("/tasks")
async def create_task(data: dict):
    title = data.get("title")           # 无校验
    return {"id": 1, "title": title}    # 无类型约束
```

✅ Good：

```python
class CreateTaskRequest(BaseModel):
    title: str = Field(..., min_length=1, max_length=200)
    priority: Literal["P0", "P1", "P2", "P3"]
    project_id: int

class TaskResponse(BaseModel):
    id: int
    title: str
    status: TaskStatus
    created_at: datetime

@router.post("", response_model=TaskResponse, status_code=201)
async def create_task(req: CreateTaskRequest) -> TaskResponse:
    return await task_service.create(req)
```

### CR-BE-API-003 状态码遵循 REST 语义

| 操作 | 成功状态码 |
|------|-----------|
| GET | 200 |
| POST 创建资源 | 201 |
| POST 触发动作（无新资源）| 200 / 202（异步）|
| PUT / PATCH | 200 / 204（无内容）|
| DELETE | 204 |

错误状态码必须与业务码一致（详见 [02-后端详细设计.md §7.2](../detail-design/02-后端详细设计.md#72-完整错误码清单exceptionscodespy)）：

| HTTP | 业务场景 |
|------|---------|
| 400 | 通用客户端错误（极少用，优先 422）|
| 401 | 未登录（BIZ_UNAUTHORIZED 2001）|
| 403 | 无权限（BIZ_FORBIDDEN 2002）|
| 404 | 资源不存在（BIZ_NOT_FOUND 1002）|
| 409 | 资源冲突（BIZ_DUPLICATE 1003）|
| 410 | 资源过期（BIZ_ACTION_EXPIRED 8002）|
| 422 | 参数校验失败（BIZ_INVALID_PARAM 1001）|
| 429 | 限流（BIZ_RATE_LIMIT 1004）|
| 500 | 服务内部错误（SYS_INTERNAL_ERROR）|

❌ Bad：

```python
@router.post("/tasks")
async def create_task(req: CreateTaskRequest):
    if not req.title:
        return {"error": "title required"}, 200   # 200 + error 字段，前端难处理
```

✅ Good：

```python
@router.post("/tasks", response_model=TaskResponse, status_code=201)
async def create_task(req: CreateTaskRequest):
    # Pydantic 自动校验，缺 title 返回 422 + BIZ_INVALID_PARAM
    return await task_service.create(req)
```

### CR-BE-API-004 复杂查询用 Pydantic 校验 query params

❌ Bad：

```python
@router.get("/tasks")
async def list_tasks(
    page: int = 1,
    page_size: int = 20,
    status: str = "",
    priority: str = "",
):
    # page=-1 / page_size=10000 / status=invalid 都不会报错
    ...
```

✅ Good：

```python
class TaskFilterParams(BaseModel):
    page: int = Field(1, ge=1)
    page_size: int = Field(20, ge=1, le=100)
    status: TaskStatus | None = None
    priority: Priority | None = None
    keyword: str | None = Field(None, max_length=100)

@router.get("/tasks")
async def list_tasks(params: TaskFilterParams = Depends()):
    return await task_service.list(params)
```

### CR-BE-API-005 写操作必须考虑幂等

POST / PUT / DELETE 必须有幂等保障：业务唯一键、actionId 机制、或显式幂等性说明。

参考 [00-通用规范 §2.1 CR-G-FUNC-004](./00-通用规范.md#cr-g-func-004-写操作必须考虑幂等)。

Copilot 写操作必经 actionId 二次确认（详见 §九 二次确认机制）。

### CR-BE-API-006 OpenAPI 文档完整

每个路由必须有 docstring（FastAPI 自动用作 OpenAPI description）。

✅ Good：

```python
@router.post(
    "",
    response_model=TaskResponse,
    status_code=201,
    summary="创建任务",
    responses={
        201: {"description": "任务创建成功"},
        403: {"description": "用户对该项目无权限"},
        409: {"description": "同项目下已存在同名任务"},
    },
)
async def create_task(req: CreateTaskRequest) -> TaskResponse:
    """
    创建一个新任务并默认 status=todo。

    业务规则：
    - 标题在同一项目下必须唯一（违反返回 409）
    - 用户必须是项目成员（违反返回 403）
    - 自动关联当前用户为创建者
    """
    return await task_service.create(req)
```

### Checklist

- [ ] 路由都在 `/api/v1/*` 下
- [ ] Request / Response 用 Pydantic Schema
- [ ] HTTP 状态码符合 REST 语义
- [ ] Query params 用 Pydantic 校验
- [ ] 写操作有幂等保障
- [ ] OpenAPI 文档完整（summary / responses / docstring）

## 二、Service / Repository 分层

> 项目分层架构（详见 [02-后端详细设计.md](../detail-design/02-后端详细设计.md)）：
>
> `Router (Controller) → Service → Repository → ORM`

### CR-BE-LAYER-001 Controller 不含业务逻辑

Router 函数应只做 3 件事：参数校验（已自动）、调 Service、组装响应。禁止在 Router 写 SQL / 业务规则 / 跨模块调用。

❌ Bad：

```python
@router.post("/tasks")
async def create_task(req: CreateTaskRequest, session: AsyncSession = Depends(get_session)):
    # Router 里写业务规则
    project = await session.get(Project, req.project_id)
    if not project:
        raise HTTPException(404)
    if user.id not in project.member_ids:
        raise HTTPException(403)
    if await session.scalar(select(Task).where(Task.title == req.title, Task.project_id == req.project_id)):
        raise HTTPException(409)
    task = Task(**req.model_dump(), creator_id=user.id, status="todo")
    session.add(task)
    await session.commit()
    return task
```

✅ Good：

```python
@router.post("", response_model=TaskResponse, status_code=201)
async def create_task(
    req: CreateTaskRequest,
    user: UserContext = Depends(current_user),
    service: TaskService = Depends(get_task_service),
) -> TaskResponse:
    task = await service.create(req, user)
    return TaskResponse.model_validate(task)
```

### CR-BE-LAYER-002 Service 不直接拼 SQL

Service 关注业务规则，DB 操作必经 Repository。

❌ Bad：

```python
class TaskService:
    async def create(self, req, user):
        # Service 里写 SQL
        existing = await self.session.scalar(
            select(Task).where(Task.title == req.title)
        )
        if existing:
            raise BizException(ErrorCode.BIZ_TITLE_DUPLICATE)
        ...
```

✅ Good：

```python
class TaskService:
    def __init__(self, task_repo: TaskRepository, project_repo: ProjectRepository):
        self.task_repo = task_repo
        self.project_repo = project_repo

    async def create(self, req: CreateTaskRequest, user: UserContext) -> Task:
        # 1. 业务校验
        project = await self.project_repo.get(req.project_id)
        if not project:
            raise BizException(ErrorCode.BIZ_PROJECT_NOT_FOUND)
        if user.id not in project.member_ids:
            raise BizException(ErrorCode.BIZ_NO_PROJECT_PERMISSION)
        if await self.task_repo.exists_by_title(req.project_id, req.title):
            raise BizException(ErrorCode.BIZ_TITLE_DUPLICATE)

        # 2. 业务执行（DB 操作走 Repository）
        return await self.task_repo.create(req, user.id)
```

### CR-BE-LAYER-003 Repository 只关心数据，禁含业务规则

Repository 只应有 CRUD 与查询拼装，禁止做权限校验、状态流转等业务判断。

❌ Bad：

```python
class TaskRepository:
    async def create(self, req, user_id):
        # Repository 里有业务规则
        if user_id not in [...]:
            raise BizException(ErrorCode.BIZ_FORBIDDEN)
        task = Task(**req.model_dump(), creator_id=user_id)
        self.session.add(task)
        ...
```

✅ Good：

```python
class TaskRepository:
    async def create(self, req: CreateTaskRequest, user_id: int) -> Task:
        task = Task(**req.model_dump(), creator_id=user_id, status=TaskStatus.TODO)
        self.session.add(task)
        await self.session.flush()
        return task

    async def exists_by_title(self, project_id: int, title: str) -> bool:
        return await self.session.scalar(
            select(exists().where(Task.project_id == project_id, Task.title == title))
        )
```

### CR-BE-LAYER-004 跨模块调用走 Service，禁止跨 Repository 调用

Service 之间可以互相调用；Repository 之间禁止互相调用。

❌ Bad：

```python
class TaskRepository:
    async def get_with_assignee(self, task_id: int):
        task = await self.session.get(Task, task_id)
        # 跨 Repository 调用，破坏边界
        task.assignee = await self.user_repo.get(task.assignee_id)
        return task
```

✅ Good：

```python
class TaskService:
    def __init__(self, task_repo, user_service):  # 注入 Service 而非 Repository
        ...

    async def get_with_assignee(self, task_id: int):
        task = await self.task_repo.get(task_id)
        task.assignee = await self.user_service.get(task.assignee_id)
        return task

# 或更优：用 SQLAlchemy 关系 + selectinload
class TaskRepository:
    async def get_with_assignee(self, task_id: int):
        return await self.session.scalar(
            select(Task).options(selectinload(Task.assignee)).where(Task.id == task_id)
        )
```

### CR-BE-LAYER-005 依赖注入用 FastAPI Depends

服务实例必经 `Depends`，便于 mock + 单测。

❌ Bad：

```python
task_service = TaskService(task_repo, ...)  # 模块级单例，难以 mock

@router.post("")
async def create_task(req):
    return await task_service.create(req)
```

✅ Good：

```python
def get_task_service(
    task_repo: TaskRepository = Depends(get_task_repo),
    project_repo: ProjectRepository = Depends(get_project_repo),
) -> TaskService:
    return TaskService(task_repo, project_repo)

@router.post("")
async def create_task(
    req: CreateTaskRequest,
    service: TaskService = Depends(get_task_service),
):
    return await service.create(req)
```

### Checklist

- [ ] Router 只做参数 + 调 Service + 组装响应
- [ ] Service 不直接写 SQL
- [ ] Repository 不含业务规则
- [ ] 跨模块调用走 Service（不跨 Repository）
- [ ] 依赖注入用 Depends

## 三、数据库

### CR-BE-DB-001 必用 SQLAlchemy ORM

禁止裸 SQL，例外（复杂 OLAP / 性能优化）需在 PR 描述中说明并经 review approve。

❌ Bad：

```python
result = await session.execute(text(
    "SELECT t.*, u.name FROM tasks t JOIN users u ON t.assignee_id = u.id WHERE t.status = :status"
), {"status": "todo"})
```

✅ Good：

```python
stmt = (
    select(Task)
    .options(joinedload(Task.assignee))
    .where(Task.status == TaskStatus.TODO)
)
result = await session.scalars(stmt)
```

### CR-BE-DB-002 N+1 查询必用 selectinload / joinedload

❌ Bad：

```python
async def list_tasks_with_project():
    tasks = await session.scalars(select(Task))
    result = []
    for task in tasks:
        # 每个 task 触发一次额外查询
        await session.refresh(task, ["project"])
        result.append(task)
    return result
```

✅ Good：

```python
async def list_tasks_with_project():
    stmt = select(Task).options(selectinload(Task.project))   # 1 + 1 次查询
    return list(await session.scalars(stmt))
```

> [!TIP]
> - `selectinload`：用 `IN (...)` 批量查询，多对一/多对多优先
> - `joinedload`：用 JOIN 一次查询，一对一优先
> - 详见 [02-后端详细设计.md](../detail-design/02-后端详细设计.md)

### CR-BE-DB-003 大表查询必带 LIMIT

任何 `SELECT` 没有 `WHERE` 强过滤的，必须有 `LIMIT`。

❌ Bad：

```python
all_tasks = await session.scalars(select(Task))   # 50 万条全捞，OOM
```

✅ Good：

```python
# 分页
async def list_tasks_paged(page: int, page_size: int):
    stmt = select(Task).limit(page_size).offset((page - 1) * page_size)
    return list(await session.scalars(stmt))

# 流式（大数据量导出）
async def stream_tasks(batch_size: int = 1000):
    offset = 0
    while True:
        batch = await session.scalars(
            select(Task).limit(batch_size).offset(offset)
        )
        items = list(batch)
        if not items:
            break
        yield items
        offset += batch_size
```

### CR-BE-DB-004 事务边界明确

涉及多写必须显式开启事务。

❌ Bad：

```python
async def transfer(from_id, to_id, amount):
    await account_repo.deduct(from_id, amount)   # 写 1
    await account_repo.add(to_id, amount)         # 写 2 失败 → from 已扣，to 没加
```

✅ Good：

```python
async def transfer(from_id, to_id, amount, session: AsyncSession):
    async with session.begin():
        await account_repo.deduct(session, from_id, amount)
        await account_repo.add(session, to_id, amount)
        # 任一失败整体回滚
```

> [!IMPORTANT]
> FastAPI 默认每个请求一个 session（`get_session` Depends），但事务必须显式 `async with session.begin()`。

### CR-BE-DB-005 Alembic Migration 必有 downgrade

每个 migration 必须实现 `downgrade()`，便于回滚。

❌ Bad：

```python
def upgrade():
    op.create_table("tasks", ...)

def downgrade():
    pass   # 不写降级，回滚时崩
```

✅ Good：

```python
def upgrade():
    op.create_table("tasks", ...)
    op.create_index("ix_tasks_project_id", "tasks", ["project_id"])

def downgrade():
    op.drop_index("ix_tasks_project_id", table_name="tasks")
    op.drop_table("tasks")
```

> [!CAUTION]
> 数据破坏性变更（drop column / alter type）的 downgrade 必须能恢复（先备份数据 → drop → downgrade 时 restore）。

### CR-BE-DB-006 索引设计必经 review

新增索引必须在 PR 描述中说明：
- 为哪些查询服务（贴 SQL）
- 索引选择性预估
- 是否会影响写性能（高频写表慎加）

✅ Good（PR 描述示例）：

```markdown
## DB 变更
新增索引 `idx_tasks_project_status_priority`：
- 用于查询：`WHERE project_id = ? AND status IN (...) ORDER BY priority DESC`
- 选择性：tasks 表 50 万行，按 (project_id, status) 分布约 200 个 group，每组 ~2500 行
- 写影响：tasks 表写 QPS < 10，可接受
```

### CR-BE-DB-007 时间字段统一规范

所有表必须有 `created_at` / `updated_at`（命名统一）；时区统一 UTC，前端转本地。

✅ Good：

```python
class Base(DeclarativeBase):
    pass

class TimestampMixin:
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), default=lambda: datetime.now(UTC), nullable=False
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        default=lambda: datetime.now(UTC),
        onupdate=lambda: datetime.now(UTC),
        nullable=False,
    )

class Task(Base, TimestampMixin):
    __tablename__ = "tasks"
    id: Mapped[int] = mapped_column(primary_key=True)
    ...
```

### CR-BE-DB-008 软删除使用 `deleted_at`

业务表（任务 / 项目 / 客户）必须支持软删除，禁止物理删除。

✅ Good：

```python
class Task(Base, TimestampMixin):
    deleted_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)

# Repository 默认过滤
class TaskRepository:
    async def find(self, **kw):
        stmt = select(Task).where(Task.deleted_at.is_(None))
        ...
```

### Checklist

- [ ] 用 ORM（裸 SQL 需 review approve）
- [ ] N+1 用 selectinload / joinedload
- [ ] 大表查询有 LIMIT
- [ ] 多写有 `async with session.begin()`
- [ ] Alembic 有 downgrade
- [ ] 新索引有 PR 说明
- [ ] 时间字段统一 UTC + created_at/updated_at
- [ ] 业务表用软删除（deleted_at）

## 四、异常处理

### CR-BE-EXC-001 业务异常必用 BizException + ErrorCode

业务级错误必须用统一的 `BizException` + 集中定义的 `ErrorCode`（详见 [02-后端详细设计.md §7.2](../detail-design/02-后端详细设计.md#72-完整错误码清单exceptionscodespy)）。

❌ Bad：

```python
if not user:
    raise HTTPException(404, "user not found")   # 散落的 HTTPException
```

✅ Good：

```python
# exceptions/codes.py（集中定义）
class ErrorCode:
    BIZ_USER_NOT_FOUND = (4001, "用户不存在", 404)

# service 中
if not user:
    raise BizException(ErrorCode.BIZ_USER_NOT_FOUND)
```

### CR-BE-EXC-002 错误码必在 codes.py 集中定义

禁止散落定义错误码字符串。前缀规范：

- `BIZ_*`：业务异常（用户能理解，如"任务不存在"）
- `SYS_*`：系统异常（用户不需理解，如"数据库连接失败"）

错误码段位规划：

| 段位 | 用途 | 示例 |
|------|------|------|
| 1xxx | 通用 | BIZ_INVALID_PARAM (1001) |
| 2xxx | 认证/权限 | BIZ_UNAUTHORIZED (2001) |
| 3xxx | 任务 | BIZ_TASK_NOT_FOUND (3001) |
| 4xxx | 项目 | BIZ_PROJECT_NOT_FOUND (4001) |
| 5xxx | 客户 | BIZ_NO_CUSTOMER_PERMISSION (5002) |
| 6xxx | 文件 | BIZ_FILE_TOO_LARGE (6001) |
| 7xxx | AI / Copilot | BIZ_LLM_TIMEOUT (7001) |
| 8xxx | actionCard | BIZ_ACTION_EXPIRED (8002) |
| 9xxx-9xxx | SYS | SYS_DB_ERROR (9001) |

### CR-BE-EXC-003 禁止 silent catch

参考 [00-通用规范 CR-G-FUNC-002](./00-通用规范.md)，并补充：

❌ Bad：

```python
try:
    await some_op()
except Exception:
    pass

try:
    await db_op()
except SQLAlchemyError:
    return None    # 静默吞掉数据库异常，bug 难追溯
```

✅ Good：

```python
try:
    await some_op()
except SpecificError as e:
    logger.warning("op_failed", error=str(e), context=ctx)
    raise BizException(ErrorCode.SYS_OP_FAILED) from e
```

### CR-BE-EXC-004 日志必含 traceId

使用 `structlog` + `trace_id_ctx`（详见 [02-后端详细设计.md §6.3](../detail-design/02-后端详细设计.md)）。

❌ Bad：

```python
logger.info(f"user {user_id} login")   # 无结构化 / 无 traceId
```

✅ Good：

```python
import structlog
logger = structlog.get_logger()

logger.info("user_login", user_id=user_id)
# trace_id 由中间件注入到 ctx，structlog 自动加入每条日志
```

### CR-BE-EXC-005 全局异常处理器统一响应格式

所有错误响应必须统一为 `{code, message, data: null, traceId}` 4 字段（详见 [02-后端详细设计.md §6.3](../detail-design/02-后端详细设计.md#63-全局异常处理器)）。

```python
@app.exception_handler(BizException)
async def biz_handler(request: Request, exc: BizException):
    return JSONResponse(
        status_code=exc.http_status,
        content={
            "code": exc.code,
            "message": exc.message,
            "data": None,
            "traceId": trace_id_ctx.get(),
        },
    )
```

> [!IMPORTANT]
> 项目已统一为 `data` 字段（不是 `detail`）。CR 时如果发现新的处理器返回了不一致结构，必须 blocking。

### CR-BE-EXC-006 异常链 `from` 不可丢

抛出新异常时必须 `raise NewException(...) from original_exc`，保留原始堆栈。

❌ Bad：

```python
try:
    await db.execute(...)
except SQLAlchemyError as e:
    raise BizException(ErrorCode.SYS_DB_ERROR)   # 丢失原始异常信息
```

✅ Good：

```python
try:
    await db.execute(...)
except SQLAlchemyError as e:
    raise BizException(ErrorCode.SYS_DB_ERROR) from e
```

### Checklist

- [ ] 业务异常用 BizException + ErrorCode
- [ ] 错误码集中定义在 codes.py
- [ ] 无 silent catch
- [ ] 日志结构化 + 含 traceId

### CR-BE-SEC-001 所有非 /auth 路由必经 current_user

未加鉴权 = 公网裸奔。CR 时必须确认所有路由都有 `Depends(current_user)`。

❌ Bad：

```python

    return await user_repo.find_all()   # 任何人能拿到全员名单
```

✅ Good：

```python
@router.get("/internal/users")
```

### CR-BE-SEC-002 行级权限必经 require_role 或自定义 Depends

✅ Good（角色级）：

```python

```

✅ Good（行级）：

```python
async def delete_project(project_id: int, user: UserContext):
```

### CR-BE-SEC-003 用户输入必经 Pydantic 校验

参考 [00-通用规范 CR-G-SEC-001](./00-通用规范.md)。重点补充：

```python
class CreateUserRequest(BaseModel):

    email: EmailStr
    # 手机号用正则
    phone: str = Field(..., pattern=r"^1[3-9]\d{9}$")
    # 文本字段必有最大长度
```

### CR-BE-SEC-004 密码必用 bcrypt + SecretStr

❌ Bad：

```python
# 明文存储 / MD5 / SHA1 都禁止
user.password = req.password
user.password = hashlib.md5(req.password.encode()).hexdigest()
```

✅ Good：

```python
from passlib.context import CryptContext
from pydantic import SecretStr

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

class CreateUserRequest(BaseModel):
    username: str
    password: SecretStr   # 防止意外打印
    @field_validator("password")
    def strong_password(cls, v: SecretStr):
        pwd = v.get_secret_value()
        if len(pwd) < 8:
            raise ValueError("密码至少 8 位")
        if not (any(c.isupper() for c in pwd) and any(c.isdigit() for c in pwd)):
            raise ValueError("密码必须含大写字母和数字")
        return v

user.password_hash = pwd_context.hash(req.password.get_secret_value())
```

## 六、性能

### CR-BE-PERF-001 IO 操作必用 async

FastAPI 是 async 框架，DB / Redis / HTTP / OSS 都必须用 async client。

❌ Bad：

```python
import requests   # 同步库，会阻塞 event loop

@router.get("/external")
async def fetch_external():
    return requests.get("https://api.example.com").json()   # 整个 worker 卡死
```

✅ Good：

```python
import httpx   # 异步 HTTP

@router.get("/external")
async def fetch_external():
    async with httpx.AsyncClient(timeout=5.0) as client:
        resp = await client.get("https://api.example.com")
        return resp.json()
```

### CR-BE-PERF-002 CPU 密集任务用线程池或 Celery

```python
import asyncio

# 短任务（< 1s）走线程池
async def render_pdf(data):
    return await asyncio.to_thread(generate_pdf_sync, data)

# 长任务（> 5s）走 Celery
@celery_app.task(bind=True, max_retries=3, default_retry_delay=60)
def generate_weekly_report(self, project_id: int):
    try:
        ...
    except Exception as e:
        raise self.retry(exc=e)
```

### CR-BE-PERF-003 Celery 任务必带超时 + 重试

❌ Bad：

```python
@celery_app.task
def process_data(data):
    # 没有超时 → 卡死 worker；没有重试 → 偶发失败丢数据
    ...
```

✅ Good：

```python
@celery_app.task(
    bind=True,
    soft_time_limit=300,        # 5 分钟软超时
    time_limit=360,              # 6 分钟硬超时
    max_retries=3,
    default_retry_delay=60,
    autoretry_for=(httpx.TimeoutException, ConnectionError),
)
def process_data(self, data):
    try:
        ...
    except SoftTimeLimitExceeded:
        logger.warning("task_timeout", task_id=self.request.id)
        raise
```

### CR-BE-PERF-004 Redis 缓存必带 TTL

参考 [00-通用规范 CR-G-PERF-005](./00-通用规范.md)。

补充缓存设计原则：

| 数据类型 | TTL 建议 |
|---------|---------|
| 用户信息 | 5 分钟（变更不频繁，可忍受短暂延迟）|
| 项目元数据 | 10 分钟 |
| 配置 / 字典 | 1 小时 + 主动失效 |
| Session / 验证码 | 业务定义 |
| AI 对话历史 | 24 小时 |
| actionId | 60 秒（写死）|

❌ Bad：

```python
await redis.set("cache:user:1", json_data)   # 永不过期
```

✅ Good：

```python
USER_CACHE_TTL = 5 * 60

async def get_user_cached(user_id: int) -> User | None:
    key = f"user:{user_id}"
    if cached := await redis.get(key):
        return User.model_validate_json(cached)
    if user := await user_repo.get(user_id):
        await redis.set(key, user.model_dump_json(), ex=USER_CACHE_TTL)
        return user
    return None

# 写入时主动失效
async def update_user(user_id: int, data):
    await user_repo.update(user_id, data)
    await redis.delete(f"user:{user_id}")
```

### CR-BE-PERF-005 大文件 / 大数据用 streaming response

❌ Bad：

```python
@router.get("/export/tasks.csv")
async def export_tasks():
    tasks = await task_repo.find_all()   # 50 万行全部加载到内存
    csv_content = generate_csv(tasks)
    return Response(csv_content, media_type="text/csv")
```

✅ Good：

```python
from fastapi.responses import StreamingResponse

@router.get("/export/tasks.csv")

    async def generate():
        yield "id,title,status\n"
        async for batch in task_repo.stream(batch_size=1000):
            for task in batch:
                yield f"{task.id},{task.title},{task.status}\n"

```

### CR-BE-PERF-006 性能基线对齐 PRD §7.1

| API 类型 | P95 |
|---------|-----|
| 简单查询 | < 200ms |
| 复杂聚合 | < 500ms |

### CR-BE-X-001 api → ai-orchestrator 必用 httpx + 超时 + 重试

❌ Bad：

### CR-BE-X-004 跨服务调用必带 traceId

### CR-BE-X-005 跨服务异常处理

调下游失败时，必须区分异常类型并映射到统一业务错误码：

```python
async def call_ai_safe(payload: dict) -> dict:
    try:
        return await call_orchestrator(payload)
    except httpx.TimeoutException as e:
        logger.warning("ai_orchestrator_timeout", payload_keys=list(payload.keys()))
        raise BizException(ErrorCode.SYS_AI_TIMEOUT) from e
    except httpx.HTTPStatusError as e:
        status = e.response.status_code
        if status == 429:
            raise BizException(ErrorCode.BIZ_AI_RATE_LIMIT) from e
        if 500 <= status < 600:
            raise BizException(ErrorCode.SYS_AI_INTERNAL_ERROR) from e
        raise BizException(ErrorCode.SYS_AI_BAD_RESPONSE) from e
    except httpx.RequestError as e:
        # 网络层错误（连接拒绝 / DNS 失败等）
        logger.error("ai_orchestrator_unreachable", error=str(e))
        raise BizException(ErrorCode.SYS_AI_UNREACHABLE) from e
```

> [!IMPORTANT]
> 严禁直接把下游 `httpx.HTTPStatusError` 透传给前端 —— 必须封装成项目自有的 `BizException + ErrorCode`，避免暴露下游服务地址 / 内部错误结构。

### CR-BE-X-006 SSE 流式响应规范

api 转发 ai-orchestrator 的 SSE 流时，必须保留 traceId 并处理客户端断开：

❌ Bad：

```python
@router.post("/copilot/chat")
async def chat(req: ChatRequest):
    async def stream():
        async with httpx.AsyncClient() as client:
            async with client.stream("POST", ai_url, json=req.model_dump()) as resp:
                async for chunk in resp.aiter_bytes():
                    yield chunk   # 客户端断开时不释放下游连接
    return StreamingResponse(stream(), media_type="text/event-stream")
```

✅ Good：

```python
@router.post("/copilot/chat")
async def chat(req: ChatRequest, request: Request):
    async def stream():
        try:
            async with httpx.AsyncClient(timeout=httpx.Timeout(read=60.0)) as client:
                async with client.stream(
                    "POST", ai_url,
                    json=req.model_dump(),
                    headers={"X-Trace-Id": trace_id_ctx.get()},
                ) as resp:
                    async for chunk in resp.aiter_bytes():
                        # 客户端断开则停止下游消费
                        if await request.is_disconnected():
                            logger.info("client_disconnected", trace_id=trace_id_ctx.get())
                            break
                        yield chunk
        except httpx.TimeoutException:
            yield b"event: error\ndata: {\"code\":7001,\"message\":\"AI 响应超时\"}\n\n"

    return StreamingResponse(
        stream(),
        media_type="text/event-stream",
        headers={"X-Trace-Id": trace_id_ctx.get(), "Cache-Control": "no-cache"},
    )
```

## 九、Copilot 写操作二次确认机制

### CR-BE-COPILOT-001 写操作必须经 actionCard + actionId

Copilot 触发的所有写操作（创建任务 / 修改状态 / 删除文件等）必须返回 actionCard，由用户二次确认后再执行（详见 [02-后端详细设计.md](../detail-design/02-后端详细设计.md) Copilot 章节）。

❌ Bad：

```python
@router.post("/copilot/chat")
async def chat(req: ChatRequest):
    # LLM 解析出"创建任务"意图，直接执行
    if intent == "create_task":
        await task_service.create(parsed_args)
    return {"reply": "已创建"}
```

✅ Good：

```python
@router.post("/copilot/chat")
async def chat(req: ChatRequest):
    if intent == "create_task":
        # 写操作 → 生成 actionId 存入 Redis（TTL 60s）+ 返回 actionCard
        action_id = uuid4().hex
        await redis.set(
            f"action:{action_id}",
            json.dumps({"type": "create_task", "args": parsed_args, "user_id": user.id}),
            ex=60,
        )
        return {
            "reply": "请确认是否创建以下任务",
            "cards": [{"type": "actionCard", "actionId": action_id, "preview": parsed_args}],
        }
```

### CR-BE-COPILOT-002 actionId 必须校验：存在性 / 归属 / 有效期

❌ Bad：

```python
@router.post("/copilot/confirm/{action_id}")
async def confirm(action_id: str):
    payload = await redis.get(f"action:{action_id}")
    args = json.loads(payload)
    return await task_service.create(args)   # 不校验归属，存在越权风险
```

✅ Good：

```python
@router.post("/copilot/confirm/{action_id}")
async def confirm(
    action_id: str,
    user: UserContext = Depends(current_user),
):
    raw = await redis.get(f"action:{action_id}")
    if raw is None:
        raise BizException(ErrorCode.BIZ_ACTION_EXPIRED)   # 8002

    data = json.loads(raw)
    if data["user_id"] != user.id:
        raise BizException(ErrorCode.BIZ_FORBIDDEN)        # 2002

    # 一次性使用：消费后立即删除（防重放）
    await redis.delete(f"action:{action_id}")
    return await dispatch_action(data)
```

### CR-BE-COPILOT-003 actionId 必须一次性消费

确认后必须立即从 Redis 删除，防止重放攻击。

### CR-BE-COPILOT-004 actionCard 字段完整性

返回前端的 actionCard 必须含有：actionId / type / preview（让用户看清要做什么）/ expireAt（前端展示倒计时）。

```python
return {
    "cards": [{
        "type": "actionCard",
        "actionId": action_id,
        "actionType": "create_task",
        "title": "创建任务确认",
        "preview": {"title": parsed_args["title"], "priority": parsed_args["priority"]},
        "expireAt": int(time.time()) + 60,
    }]
}
```

### CR-BE-LINT-002 类型注解强制

所有函数签名必须有完整类型注解（参数 + 返回值），mypy strict 模式下不允许 `Any` 出现在公开 API。

❌ Bad：

```python
def process(data):       # 无类型
    return data["x"]
```

✅ Good：

```python
def process(data: TaskInput) -> TaskOutput:
    return TaskOutput(x=data.x)
```
