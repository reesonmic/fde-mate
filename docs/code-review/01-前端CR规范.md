## 一、Vue 组件规范

### CR-FE-VUE-001 强制 Composition API + `<script setup lang="ts">`

新组件禁止使用 Options API，禁止使用 JavaScript（必须 TS）。

❌ Bad：

```vue
<script>
export default {
  data() {
    return { count: 0 }
  },
  methods: {
    inc() { this.count++ }
  }
}
</script>
```

✅ Good：

```vue
<script setup lang="ts">
import { ref } from 'vue'

const count = ref(0)
const inc = () => count.value++
</script>
```

### CR-FE-VUE-002 Props 必带类型 + 默认值

使用 `defineProps` + `withDefaults` 显式声明类型与默认值。

❌ Bad：

```vue
<script setup>
const props = defineProps(['title', 'size'])  // 无类型 / 无默认值
</script>
```

✅ Good：

```vue
<script setup lang="ts">
interface Props {
  title: string
  size?: 'sm' | 'md' | 'lg' | 'xl'
  closable?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  size: 'md',
  closable: true,
})
</script>
```

### CR-FE-VUE-003 Emits 必声明类型

❌ Bad：

```vue
<script setup>
const emit = defineEmits(['update', 'close'])  // 无 payload 类型
emit('update', someValue)  // payload 类型未约束
</script>
```

✅ Good：

```vue
<script setup lang="ts">
const emit = defineEmits<{
  update: [value: string]
  close: []
  select: [item: TaskItem, index: number]
}>()

emit('update', 'new value')
emit('select', taskItem, 3)
</script>
```

### CR-FE-VUE-004 单文件 ≤ 300 行（含 template/script/style）

单文件超过 300 行必须拆子组件。子组件按业务/视图层级放置：

```
components/
├── common/         # 跨业务通用（无业务语义）
├── business/       # 业务组件（含具体业务语义）
└── views/          # 仅页面级使用的子组件
```

### CR-FE-VUE-005 命名规范

- **组件名**：PascalCase（`TaskCard.vue`、`HealthRing.vue`）
- **template 中使用**：PascalCase 或 kebab-case（项目内统一一种，本项目用 PascalCase）
- **props / emits**：camelCase 定义，template 中 kebab-case 使用
- **常量**：UPPER_SNAKE_CASE（`MAX_FILE_SIZE`）
- **composable**：`use` 前缀（`useTaskList.ts`）

❌ Bad：`task_card.vue` / `taskCard.vue` / `Tcomp.vue`
✅ Good：`TaskCard.vue` / `useTaskList.ts` / `MAX_RETRY = 3`

### CR-FE-VUE-006 响应式陷阱

**陷阱 1**：解构 reactive 会失去响应性。

❌ Bad：

```typescript
const state = reactive({ count: 0, name: 'foo' })
const { count } = state              // count 不再响应
const fn = () => state.count++       // UI 不更新
```

✅ Good：

```typescript
const state = reactive({ count: 0, name: 'foo' })
const { count } = toRefs(state)      // 用 toRefs 保持响应
// 或直接用 ref
const count = ref(0)
const name = ref('foo')
```

**陷阱 2**：在 `setup()` 同步访问 ref.value 后再 await，可能拿到过时值。

✅ Good：

```typescript
const userId = ref<string>('')
const loadUser = async () => {
  const id = userId.value           // 在 await 前读
  const data = await api.getUser(id)
  // 校验是否仍是当前选中（防止竞态）
  if (id === userId.value) state.user = data
}
```

### Checklist

- [ ] 全部使用 Composition API + `<script setup lang="ts">`
- [ ] Props 用 `withDefaults` + interface 声明
- [ ] Emits 有类型声明
- [ ] 单文件 ≤ 300 行
- [ ] 命名遵循约定（PascalCase / camelCase / use 前缀）
- [ ] 无解构 reactive 失去响应性问题
- [ ] await 前后竞态已防护

## 二、TypeScript 类型规范

### CR-FE-TS-001 禁用 `any`

需要"任意类型"时用 `unknown` + 类型守卫；外部库无类型定义时用 `as` 显式标注一次。

❌ Bad：

```typescript
function parse(data: any): any {
  return data.items.map((x: any) => x.name)
}
```

✅ Good：

```typescript
interface ApiResponse {
  items: Array<{ name: string; id: number }>
}

function parse(data: ApiResponse): string[] {
  return data.items.map(item => item.name)
}

// 真的不知道类型时用 unknown + 守卫
function safeParse(data: unknown): string[] {
  if (typeof data === 'object' && data !== null && 'items' in data) {
    return (data as ApiResponse).items.map(i => i.name)
  }
  return []
}
```

eslint 规则：`@typescript-eslint/no-explicit-any: error`。

### CR-FE-TS-002 API 类型从 OpenAPI 自动生成

后端 API 类型必须从 `shared-protos/openapi/api.json` 通过 `npm run gen:types` 生成，禁止手写。

❌ Bad：

```typescript
// 手写一份 Task 类型，与后端 schema 容易不一致
interface Task {
  id: number
  title: string
  // 后端加了 priority 字段，前端忘了同步 → 编译时不报错，运行时崩
}
```

✅ Good：

```typescript
import type { components } from '@/types/api'   // 自动生成的
type Task = components['schemas']['Task']        // 与后端 schema 始终一致
```

### CR-FE-TS-003 类型 import 用 `import type`

仅用于类型检查的 import 必须加 `type`，让 Vite/TS 在 build 时正确 tree-shake。

❌ Bad：

```typescript
import { Task, TaskService } from '@/types'  // Task 仅类型用，TaskService 是值
```

✅ Good：

```typescript
import type { Task } from '@/types'
import { TaskService } from '@/services/task'
```

eslint 规则：`@typescript-eslint/consistent-type-imports: error`。

### CR-FE-TS-004 复杂泛型必加注释

泛型嵌套 ≥ 3 层时必须有注释解释意图。

❌ Bad：

```typescript
type Result<T, E, M> = T extends object ? { [K in keyof T]: M extends true ? Promise<T[K]> : T[K] } : never
```

✅ Good：

```typescript
/**
 * 把对象的所有字段包装成 Promise，但仅当 M=true 时启用。
 * 用于：异步 form 字段映射 / lazy fetch hook 的类型推导。
 */
type Result<T, E, M> = T extends object
  ? { [K in keyof T]: M extends true ? Promise<T[K]> : T[K] }
  : never
```

### CR-FE-TS-005 禁用非空断言 `!`（除非明确知道一定非空）

❌ Bad：

```typescript
const user = users.find(u => u.id === currentId)!  // user 可能 undefined，! 只是骗 TS
```

✅ Good：

```typescript
const user = users.find(u => u.id === currentId)
if (!user) {
  message.error('用户不存在')
  return
}
// 这里 TS 收窄类型，user 一定非空
```

### Checklist

- [ ] 无 `any`（用 `unknown` + 类型守卫替代）
- [ ] API 类型来自 `gen:types` 自动生成
- [ ] 类型 import 用 `import type`
- [ ] 复杂泛型有注释
- [ ] 无未经检查的 `!` 非空断言

## 三、状态管理（Pinia）

### CR-FE-STATE-001 Store 按业务域拆分

按业务领域（task / project / customer / auth），不按页面（dashboardStore ❌）。

❌ Bad：

```typescript
// stores/dashboard.ts —— 把任务、项目、客户全塞进来，难以复用
export const useDashboardStore = defineStore('dashboard', {
  state: () => ({ tasks: [], projects: [], customers: [], notifications: [] })
})
```

✅ Good：

```typescript
// stores/task.ts / stores/project.ts / stores/customer.ts 各自独立
// dashboard 页面组合多个 store
const taskStore = useTaskStore()
const projectStore = useProjectStore()
```

### CR-FE-STATE-002 派生数据用 getters

❌ Bad：

```typescript
state: () => ({
  tasks: [] as Task[],
  todoCount: 0,           // 派生数据放 state，需要手动维护同步
})
actions: {
  addTask(t) {
    this.tasks.push(t)
    if (t.status === 'todo') this.todoCount++  // 容易忘
  }
}
```

✅ Good：

```typescript
state: () => ({ tasks: [] as Task[] })

getters: {
  todoCount: (state) => state.tasks.filter(t => t.status === 'todo').length,
  todoTasks: (state) => state.tasks.filter(t => t.status === 'todo'),
}
```

### CR-FE-STATE-003 Action 必处理异常

Action 内调 API 必须 try/catch，失败要 toast + 不污染 state。

❌ Bad：

```typescript
actions: {
  async loadTasks() {
    this.tasks = await api.getTasks()  // 失败：tasks 变 undefined，UI 崩
  }
}
```

✅ Good：

```typescript
actions: {
  async loadTasks() {
    this.loading = true
    try {
      this.tasks = await api.getTasks()
    } catch (e) {
      message.error('加载任务失败')
      // 保留旧数据，不要污染
    } finally {
      this.loading = false
    }
  }
}
```

### CR-FE-STATE-004 跨 Store 调用规范

Store 之间禁止循环依赖。允许 A 依赖 B，但不允许 A↔B。

❌ Bad：

```typescript
// stores/task.ts
import { useProjectStore } from './project'

// stores/project.ts
import { useTaskStore } from './task'   // 循环依赖
```

✅ Good：

```typescript
// 提取公共依赖到第三方 store 或 composable
// composables/useTaskProjectBridge.ts
export function useTaskProjectBridge() {
  const taskStore = useTaskStore()
  const projectStore = useProjectStore()
  return { ... }
}
```

### CR-FE-STATE-005 持久化字段白名单

仅持久化必要字段（如登录态），禁止持久化业务数据（任务 / 项目）。

❌ Bad：

```typescript
// 持久化整个 store，导致 localStorage 暴涨 + 数据陈旧
persist: true
```

✅ Good：

```typescript
persist: {
  paths: ['user', 'theme'],   // 仅持久化用户登录态与主题
}
```

> [!WARNING]
> Token 类敏感字段优先用 httpOnly cookie，不要存 localStorage（详见 §六 安全）。

### Checklist

- [ ] Store 按业务域拆分
- [ ] 派生数据用 getters
- [ ] Action 有 try/catch + toast + 不污染 state
- [ ] 无 Store 循环依赖
- [ ] 持久化字段已白名单限制

## 四、API 调用

### CR-FE-API-001 必经 `apis/http.ts` 实例

所有 HTTP 请求必须经统一 axios 实例（带 auth/error/loading 拦截器），禁止直接 `fetch` / `new XMLHttpRequest`。

❌ Bad：

```typescript
const data = await fetch('/api/v1/tasks').then(r => r.json())
// 没有 auth header / 没有错误处理 / 没有 loading 状态
```

✅ Good：

```typescript
import http from '@/apis/http'

const tasks = await http.get<Task[]>('/api/v1/tasks')
// 自动带 token / 401 自动跳登录 / 全局 loading 状态
```

### CR-FE-API-002 SSE 必经 `apis/sse.ts`

SSE 流（AI 对话）必经统一封装的 SSE 客户端（基于 `@microsoft/fetch-event-source`），禁止裸用 `EventSource`。

❌ Bad：

```typescript
const es = new EventSource('/api/v1/copilot/chat')
// EventSource 不支持 POST / 不支持 header / 不支持取消
```

✅ Good：

```typescript
import { createSSE } from '@/apis/sse'

const sse = createSSE('/api/v1/copilot/chat', {
  method: 'POST',
  body: { message: 'hello' },
  onMessage: (event) => { ... },
  onError: (e) => { ... },
  signal: abortController.signal,  // 支持取消
})
```

### CR-FE-API-003 错误统一拦截 + 业务级 try/catch

通用错误（401/403/500）走拦截器；业务级错误（如表单校验失败）走 try/catch。

✅ Good：

```typescript
// http.ts 拦截器：401 自动跳登录，5xx 弹通用错误 toast
http.interceptors.response.use(
  res => res.data,
  err => {
    if (err.response?.status === 401) router.push('/login')
    if (err.response?.status >= 500) message.error('服务异常，请稍后重试')
    return Promise.reject(err)
  }
)

// 业务代码：捕获业务码做特定处理
try {
  await taskApi.create(req)
  message.success('创建成功')
} catch (e: any) {
  if (e.response?.data?.code === 3002) {
    message.warning('任务标题已存在')
  } else {
    throw e   // 其他交给拦截器
  }
}
```

### CR-FE-API-004 Mock 数据走 MSW

开发期 mock 必经 MSW（VITE_USE_MOCK=true 切换），禁止在业务代码里写 `if (mock) return fakeData`。

❌ Bad：

```typescript
async function getTasks() {
  if (import.meta.env.DEV) {
    return [{ id: 1, title: 'fake' }]   // 业务代码污染
  }
  return await http.get('/api/v1/tasks')
}
```

✅ Good：

```typescript
// 业务代码无感
async function getTasks() {
  return await http.get<Task[]>('/api/v1/tasks')
}

// apis/mock/handlers.ts
import { http, HttpResponse } from 'msw'
export const handlers = [
  http.get('/api/v1/tasks', () => HttpResponse.json([{ id: 1, title: 'fake' }])),
]
```

### CR-FE-API-005 请求取消（防竞态）

可被快速重复触发的请求（搜索框 / 切换 tab）必须支持 `AbortController`。

✅ Good：

```typescript
const controller = ref<AbortController | null>(null)

const search = async (kw: string) => {
  controller.value?.abort()                 // 取消上一次
  controller.value = new AbortController()
  results.value = await http.get('/api/v1/search', {
    params: { kw },
    signal: controller.value.signal,
  })
}
```

### Checklist

- [ ] 所有 HTTP 走 `apis/http.ts`
- [ ] 所有 SSE 走 `apis/sse.ts`
- [ ] 通用错误拦截器处理，业务码 try/catch 处理
- [ ] Mock 走 MSW，业务代码无感
- [ ] 防竞态请求有 AbortController

## 五、性能

### CR-FE-PERF-001 v-for 必带稳定 :key（不用 index）

❌ Bad：

```vue
<div v-for="(item, index) in tasks" :key="index">{{ item.title }}</div>
<!-- 列表重排时，index 不变但内容变了，Vue diff 出错 -->
```

✅ Good：

```vue
<div v-for="item in tasks" :key="item.id">{{ item.title }}</div>
```

### CR-FE-PERF-002 大列表用虚拟滚动

列表渲染 ≥ 200 条必须用 `vue-virtual-scroller` 或 antdv 的 `VirtualList`。

❌ Bad：

```vue
<!-- 5000 条任务全部渲染，DOM 节点爆炸 -->
<TaskItem v-for="t in allTasks" :key="t.id" :task="t" />
```

✅ Good：

```vue
<RecycleScroller :items="allTasks" :item-size="60" key-field="id" v-slot="{ item }">
  <TaskItem :task="item" />
</RecycleScroller>
```

### CR-FE-PERF-003 路由级 + 组件级懒加载

❌ Bad：

```typescript
import Dashboard from '@/views/Dashboard.vue'
import Tasks from '@/views/Tasks.vue'
import AiChat from '@/views/AiChat.vue'   // 全部塞进首屏 bundle
```

✅ Good：

```typescript
const routes = [
  { path: '/dashboard', component: () => import('@/views/Dashboard.vue') },
  { path: '/tasks',     component: () => import('@/views/Tasks.vue') },
  { path: '/ai-chat',   component: () => import('@/views/AiChat.vue') },
]
```

重型组件（图表 / 富文本编辑器 / Markdown 渲染器）也要懒加载：

```typescript
const MarkdownRenderer = defineAsyncComponent(() => import('@/components/MarkdownRenderer.vue'))
```

### CR-FE-PERF-004 避免在 template 内调用方法（用 computed）

❌ Bad：

```vue
<!-- formatPrice 每次重渲染都执行，且不缓存 -->
<div v-for="item in items" :key="item.id">{{ formatPrice(item.price, exchangeRate) }}</div>
```

✅ Good：

```vue
<div v-for="item in formattedItems" :key="item.id">{{ item.formattedPrice }}</div>

<script setup>
const formattedItems = computed(() =>
  items.value.map(i => ({ ...i, formattedPrice: formatPrice(i.price, exchangeRate.value) }))
)
</script>
```

### CR-FE-PERF-005 图片 lazy loading

`<img>` 必须加 `loading="lazy"`（首屏关键图除外）。

```vue
<img :src="avatar" loading="lazy" alt="user avatar" />
```

### CR-FE-PERF-006 满足 PRD §7.1 性能基线

| 指标 | 基线 |
|------|------|
| 首屏 FCP | < 1.5s |
| 路由切换 | < 200ms |
| @ 引用弹窗响应 | < 100ms |
| AI SSE 首 token | < 1s（前端不阻塞）|

CR 时若改动可能影响首屏（新增大依赖 / 同步 import），必须在 PR 描述中贴 `npm run build` 后的 chunk 大小对比。

### Checklist

- [ ] v-for 都有稳定 :key（不用 index）
- [ ] 大列表用虚拟滚动
- [ ] 路由 / 重型组件懒加载
- [ ] 模板内无重复方法调用（用 computed）
- [ ] 非首屏图片有 loading="lazy"
- [ ] 首屏改动有 bundle 体积对比

## 六、安全

### CR-FE-SEC-001 v-html 必经 DOMPurify

任何 v-html 渲染用户内容必须经 `DOMPurify.sanitize()`，否则 blocking。

❌ Bad：

```vue
<!-- 用户在评论里写 <img src=x onerror=alert(1)> 会执行 -->
<div v-html="comment.content"></div>
```

✅ Good：

```vue
<script setup>
import DOMPurify from 'dompurify'
const safeContent = computed(() => DOMPurify.sanitize(comment.content))
</script>
<template>
  <div v-html="safeContent"></div>
</template>
```

> [!CAUTION]
> Markdown 渲染器（marked / vue-markdown）输出同样要 DOMPurify，因为可以注入 `<script>` 标签。

### CR-FE-SEC-002 跳转 URL 必白名单校验

外部跳转必须校验 URL 协议与域名，避免开放重定向。

❌ Bad：

```typescript
// 用户点的链接是 javascript:alert(1) 也会执行
window.location.href = redirectUrl
```

✅ Good：

```typescript
const ALLOWED_REDIRECT_HOSTS = ['fde.alibaba-inc.com', 'aone.alibaba-inc.com']

function safeRedirect(url: string) {
  try {
    const parsed = new URL(url, window.location.origin)
    if (parsed.protocol !== 'https:' && parsed.protocol !== 'http:') return false
    if (!ALLOWED_REDIRECT_HOSTS.some(h => parsed.hostname.endsWith(h))) return false
    window.location.href = parsed.href
    return true
  } catch {
    return false
  }
}
```

### CR-FE-SEC-003 localStorage 禁存敏感信息

Token / 密码 / 客户敏感数据禁止存 localStorage / sessionStorage（XSS 即丢）。

❌ Bad：

```typescript
localStorage.setItem('accessToken', token)
localStorage.setItem('userPhone', user.phone)
```

✅ Good：

```typescript
// Token 走 httpOnly cookie（后端 set，前端读不到，XSS 偷不走）
// 仅存 UI 状态
localStorage.setItem('theme', 'dark')
localStorage.setItem('lastVisitedPath', '/tasks')
```

### CR-FE-SEC-004 用户输入渲染前校验

表单输入虽然有 backend 校验，前端也要做基础校验（提升体验 + 防 UI 注入）。

✅ Good：

```vue
<a-input v-model:value="title" :maxlength="200" show-count />
<a-form-item :rules="[{ required: true, message: '请输入标题' }, { max: 200 }]">
```

### CR-FE-SEC-005 第三方依赖审计

新增 npm 依赖必须：
- 在 PR 描述中说明用途与替代方案对比
- 检查 npm audit / Snyk 是否有高危漏洞
- 优先选活跃维护的（最近 6 个月有 commit）

### Checklist

- [ ] v-html 都经 DOMPurify
- [ ] 跳转 URL 都做白名单校验
- [ ] 敏感信息未存 localStorage
- [ ] 表单输入有前端校验（长度 / 格式）
- [ ] 新增依赖通过 audit 检查

## 七、测试

### CR-FE-TEST-001 组件单测用 @vue/test-utils + Vitest

### CR-FE-TEST-002 业务组件必测交互行为

❌ Bad：只测渲染，不测交互。

```typescript
test('renders title', () => {
  const wrapper = mount(TaskCard, { props: { task: { title: 'hi' } } })
  expect(wrapper.text()).toContain('hi')
})
```

✅ Good：

```typescript
test('emits update when status toggled', async () => {
  const wrapper = mount(TaskCard, { props: { task: { id: 1, status: 'todo', title: 'hi' } } })

  await wrapper.find('[data-test="status-toggle"]').trigger('click')

  expect(wrapper.emitted('update')).toBeTruthy()
  expect(wrapper.emitted('update')![0]).toEqual([{ id: 1, status: 'done' }])
})
```

### CR-FE-TEST-003 Mock 走 MSW

```typescript
import { server } from '@/apis/mock/server'

beforeAll(() => server.listen())

```

## 八、Copilot 专项（4 助手通用）

### CR-FE-COP-001 actionCard 渲染必校验 actionId

`actionId` 60s 过期，渲染时必须校验未过期 + 未被使用。

❌ Bad：

```vue
<button @click="execute(card.actionId)">确认</button>
<!-- 用户 5 分钟后回来点，actionId 已过期，直接报 410 -->
```

✅ Good：

```vue
<script setup>
const isExpired = computed(() => Date.now() > card.expiresAt)
const isUsed = computed(() => card.status !== 'pending')
</script>

<template>
  <button :disabled="isExpired || isUsed" @click="execute(card.actionId)">
    {{ isExpired ? '已过期' : isUsed ? '已处理' : '确认' }}
  </button>
  <a-alert v-if="isExpired" type="warning">
    该操作已过期，请重新发起
  </a-alert>
</template>
```

> 后端 actionId 异常码（410/403/422）见 [02-后端详细设计.md §7.2](../detail-design/02-后端详细设计.md)。

### CR-FE-COP-002 SSE 中断必有友好提示 + 重试

❌ Bad：

```typescript
sse.onError = () => {
  message.error('对话失败')
  // 用户失去上下文，无法继续
}
```

✅ Good：

```typescript
sse.onError = (e) => {
  appendMessage({
    role: 'assistant',
    content: '⚠️ 对话连接中断，可能是网络波动。',
    actions: [
      { label: '重试', handler: () => retry(lastUserMessage) },
      { label: '保存当前对话', handler: () => exportChat() },
    ],
  })
}
```

### CR-FE-COP-003 @ 引用 tag 必有移除按钮

❌ Bad：用户加了 @ 引用后无法移除，必须重新发消息。

✅ Good：每个 tag 显示 × 按钮：

```vue
<a-tag v-for="(ref, idx) in mentions" :key="ref.id" closable @close="mentions.splice(idx, 1)">
  @{{ ref.type }}: {{ ref.title }}
</a-tag>
```

### CR-FE-COP-004 Copilot 三态宽度切换无 layout shift

切换 `400px → 56px → 0px` 时主区域必须平滑过渡（使用 transition + GPU 加速），不可重新 layout 整个页面。

```css
.copilot-panel {
  transition: width 200ms ease;
  will-change: width;     /* GPU hint */
}
```

### CR-FE-COP-005 Context 区显示要紧凑

@ 引用最多显示 5 项，超过折叠，避免占满屏幕。

```vue
<div class="context-list">
  <ContextItem v-for="ref in mentions.slice(0, 5)" :key="ref.id" :ref="ref" />
  <a v-if="mentions.length > 5" @click="showAll = true">
    还有 {{ mentions.length - 5 }} 项 ↓
  </a>
</div>
```

### CR-FE-COP-006 4 类 AI 卡片渲染白名单

仅渲染 4 类已知卡片：`actionCard / report / nextSteps / searchResults`，未知 type 必须 fallback 到 plain text，禁止盲目渲染（防 Prompt 注入构造恶意卡片）。

```typescript
const RENDERABLE_CARD_TYPES = ['actionCard', 'report', 'nextSteps', 'searchResults'] as const
type CardType = typeof RENDERABLE_CARD_TYPES[number]

function renderCard(card: { type: string; data: unknown }) {
  if (!RENDERABLE_CARD_TYPES.includes(card.type as CardType)) {
    return <pre>{JSON.stringify(card.data)}</pre>
  }
  // 各类型独立渲染
}
```

- [ ] @ 引用 tag 可单独移除
- [ ] Copilot 宽度切换有 transition
- [ ] Context 显示紧凑（≥5 折叠）
